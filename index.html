🔐 Mécanisme concret : Preuve photographique pour validation d'identité du livreur

1. Phase de pré-enrôlement du livreur (One-time setup)

Avant toute activité, le livreur doit fournir des éléments d'identité visuels stockés dans son profil système :

Élément Description Usage
📸 Photo de profil Portrait clair du visage Affiché dans l'app client/vendeur pour reconnaissance visuelle
🛵 Photo du véhicule Véhicule + plaque d'immatriculation visible Vérification physique sur le terrain
🪪 Photo pièce d'identité / badge professionnel Document officiel ou badge ViteComm Validation administrative par l'admin
📍 Géolocalisation initiale Coordonnées GPS du lieu d'enrôlement Ancrage de confiance pour les futures courses
Ces éléments sont consultables en temps réel par le client et le vendeur via l'application lors de la mise en relation.

2. Flux opérationnel : Collection chez le vendeur

[Arrivée du livreur chez le vendeur]
        ↓
1. Le livreur ouvre sa course dans l'app → affiche le code de vérification (ex: VC-7821)
        ↓
2. Le vendeur saisit/scanne ce code dans son interface → le système confirme :
   • Que le livreur est bien affecté à cette commande
   • Que le vendeur correspond à l'étal attendu
        ↓
3. [Étape preuve photographique OBLIGATOIRE]
   → Le livreur (ou le vendeur) prend une photo via l'app montrant :
      • Le visage du livreur (selfie guidé ou mode double caméra)
      • Le code de vérification affiché sur l'écran du livreur
      • Les produits prêts à être collectés
      • (Optionnel) L'enseigne/repère visuel de l'étal
        ↓
4. L'app ajoute automatiquement en métadonnées :
   • Horodatage précis (timestamp)
   • Coordonnées GPS (géolocalisation)
   • ID de la course + ID livreur + ID vendeur
        ↓
5. La photo est uploadée (ou mise en file d'attente si hors-ligne) et liée à l'entité PREUVE_COLLECTE
        ↓
6. Le vendeur confirme la remise → statut de la collecte passe à "validée"

3. Flux opérationnel : Livraison au client

[Arrivée du livreur chez le client]
        ↓
1. Le client reçoit une notification : "Votre livreur [Nom] arrive avec [Nb] articles"
   → L'app affiche la photo de profil du livreur + photo de son véhicule
        ↓
2. À l'arrivée, le livreur présente à nouveau le code de vérification
        ↓
3. [Preuve photographique de livraison]
   → Photo obligatoire montrant :
      • Le livreur remettant les articles au client (ou les articles devant le client)
      • Le code de vérification visible
      • (Optionnel) Le client signant/acquiesçant dans l'app
        ↓
4. Métadonnées automatiques : timestamp + GPS + ID course
        ↓
5. Si le client accepte : paiement déclenché → répartition des fonds
   Si litige : la photo sert de pièce à conviction pour l'arbitrage admin

4. En cas de litige : rôle de la preuve photographique

Extrait du CDC (Section 4.4) :
"En cas de conflit, l'administrateur arbitre les litiges en confrontant les preuves photographiques, les historiques de commande et les feedbacks…"

Concrètement, l'admin accède à un dossier de litige contenant :

📁 Litige #LIT-2026-042
├── 📄 Résumé : "Client refuse 2 articles – prétend ne pas les avoir reçus"
├── 📸 Preuve collection vendeur A : [photo + GPS + timestamp]
├── 📸 Preuve collection vendeur B : [photo + GPS + timestamp]
├── 📸 Preuve livraison client : [photo + GPS + timestamp]
├── 👤 Profil livreur : [photo profil + véhicule + note réputation]
├── 💬 Feedback client : "Livreur sympathique mais articles manquants"
└── ⚖️ Décision admin : [à compléter]

La photo permet de trancher :

  • ✅ Le livreur était bien sur place (GPS + visage)
  • ✅ Les produits ont bien été remis (visuels des articles)
  • ✅ Le code de vérification a été utilisé (preuve d'authentification)

5. Implémentation technique (résumé pour le MLD)

Dans le Modèle Logique des Données, cela se traduit par l'entité : 

PREUVE_COLLECTE(
  id_preuve PK,
  date_heure,
  url_photo,          -- lien vers le stockage cloud (ex: AlwaysData)
  statut_validation,  -- "en_attente", "validée", "litige"
  #id_commande FK,
  #id_vendeur FK,     -- qui a validé la remise
  #id_livreur FK,     -- qui a effectué la collecte
  gps_latitude,
  gps_longitude,
  device_id           -- pour tracer l'appareil ayant pris la photo
)

✅ En résumé : ce que la preuve photographique apporte concrètement

Objectif Mécanisme Bénéfice
🔍 Confirmer l'identité du livreur Photo de profil + photo en temps réel avec code Le client/vendeur reconnaît visuellement la personne attendue
📍 Prouver la présence sur site Géolocalisation + timestamp dans les métadonnées Impossible de falsifier le lieu/heure de collecte
🤝 Sécuriser la remise physique Photo montrant produits + code + acteur Preuve tangible en cas de désaccord
⚖️ Faciliter l'arbitrage Dossier photo centralisé pour l'admin Décision rapide, factuelle, équitable
📈 Alimenter la réputation Photos validées → score livreur/vendeur Incitation à la rigueur, dissuasion des fraudes
